# Ревью Done: готовность к работе большой команды

Сентябрь 2026. Цель: довести Done до продукта, которым каждый день пользуется команда из десятков человек, ориентируясь на Notion Projects.

## Что изучено в Notion

- Сайдбар: [Navigate with the sidebar](https://www.notion.com/help/navigate-with-the-sidebar) и редизайн сайдбара в [Notion 3.4](https://www.notion.com/releases/2026-03-26). При наведении на страницу появляются `•••` и `+`, иконка сменяется стрелкой раскрытия; свернутый сайдбар всплывает поверх страницы при наведении на левый край.
- Проекты и задачи: [Projects and tasks](https://www.notion.com/help/guides/getting-started-with-projects-and-tasks). Проект это родитель задач, прогресс считается по выполненным задачам, у задач есть исполнитель, срок, приоритет, спринт.
- Спринты: [Sprints](https://www.notion.com/help/sprints). Текущий спринт, планирование (текущий, следующий, бэклог), завершение спринта с переносом незавершенного, длина 1-8 недель.
- Входящие: [Updates and notifications](https://www.notion.com/help/updates-and-notifications). Упоминания, ответы, назначения, фильтры «непрочитанные / все / архив», счетчик непрочитанного в сайдбаре.

## Что было хорошо

- Аккуратная модель данных и стор: неизменяемые обновления, корзина с отменой, защита от циклов в иерархии и зависимостях.
- Сервер проверяет права независимо от интерфейса и не отдает скрытые проекты; пароли через scrypt, HttpOnly сессии, проверка origin.
- Богатые представления: роадмап, бэклог как база Notion, доска, календарь, карта, файлы, документы на BlockNote.
- Тесты (Vitest и Playwright), строгий TypeScript, CI с `npm run check`.

## Сайдбар и анимации

- Одна мягкая подсветка скользит за указателем между строками вместо вспышки фона у каждой строки.
- Иконка страницы плавно сменяется стрелкой раскрытия, стрелка поворачивается с легкой пружиной, кнопки `•••` и `+` выезжают справа.
- Свернутый сайдбар всплывает поверх страницы при наведении на левый край или на кнопку меню (она превращается в `»`), как в Notion; клик закрепляет его.
- Бейдж непрочитанного во входящих, живой индикатор синхронизации, аватары коллег в сети.
- Все анимации уважают системную настройку «уменьшить движение».

## Проверки

- `npm run check`: TypeScript, 70 unit тестов, production сборка.
- `npm run e2e`: вход и роли; два аккаунта, где упоминание появляется во входящих коллеги без перезагрузки и оба видят друг друга на странице проекта; спринты и входящие в демо; мобильная раскладка.

## Что остается на следующие итерации

1. Посимвольное совместное редактирование документов (Yjs). Сейчас одновременная правка текста одной страницы сохраняется по принципу «последняя запись побеждает».
2. После каждой чужой правки клиент заново загружает пространство целиком. Для очень больших пространств нужны дельты в потоке событий.
3. SSE и присутствие живут в памяти одного процесса. Для нескольких инстансов нужен общий брокер (например, Redis pub/sub).
4. Файлы хранятся в SQLite и загружаются через JSON base64 (до 20 MB). Для большой команды нужен объектный стор.
5. Нет почты, OAuth и восстановления пароля; уведомления только внутри продукта.
6. Корзина участников без прав администратора не сохраняется на сервере: удаление можно отменить из тоста, а восстановление из корзины доступно администраторам.
7. Журнал аудита покрывает аккаунты и доступы, но не изменения контента.
