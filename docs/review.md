# Ревью Done: готовность к работе большой команды

Сентябрь 2026. Цель: довести Done до продукта, которым каждый день пользуется команда из десятков человек, ориентируясь на Notion Projects.

## Что изучено в Notion

- Сайдбар: [Navigate with the sidebar](https://www.notion.com/help/navigate-with-the-sidebar) и редизайн сайдбара в [Notion 3.4](https://www.notion.com/releases/2026-03-26). При наведении на страницу появляются `•••` и `+`, иконка сменяется стрелкой раскрытия; свернутый сайдбар всплывает поверх страницы при наведении на левый край.
- Проекты и задачи: [Projects and tasks](https://www.notion.com/help/guides/getting-started-with-projects-and-tasks). Проект это родитель задач, прогресс считается по выполненным задачам, у задач есть исполнитель, срок, приоритет, спринт.
- Спринты: [Sprints](https://www.notion.com/help/sprints). Текущий спринт, планирование (текущий, следующий, бэклог), завершение спринта с переносом незавершенного, длина 1-8 недель.
- Входящие: [Updates and notifications](https://www.notion.com/help/updates-and-notifications). Упоминания, ответы, назначения, фильтры «непрочитанные / все / архив», счетчик непрочитанного в сайдбаре.

## Что было хорошо

- Аккуратная модель данных и стор: неизменяемые обновления, корзина с отменой, защита от циклов в иерархии и зависимостях.
- Сервер проверяет права независимо от интерфейса и не отдает скрытые проекты; пароли через scrypt, HttpOnly сессии, проверка origin.
- Богатые представления: роадмап, бэклог как база Notion, доска, календарь, карта, файлы, документы на BlockNote.
- Тесты (Vitest и Playwright), строгий TypeScript, CI с `npm run check`.

## Сайдбар и анимации

Первая версия (скользящая подсветка, выезжающие кнопки, пружины) оказалась слишком «плавной» по сравнению с Notion. Сайдбар переделан по замерам со скриншотов Notion (таблица в `docs/design-reference.md`):

- структура нового Notion: сверху переключатель, входящие с бейджем и новая страница; поиск; вкладки «Главная / Мои задачи / Календарь»; секции; переключатель пространства внизу;
- строки 30 px с зазором 1 px, поэтому выбранная и наведенная строки не сливаются;
- при наведении на любую строку (в том числе в «Недавних» и «Избранном») иконка сразу меняется на стрелку раскрытия, справа появляются `+` и `•••`;
- никаких плавных переходов фона, подъемов карточек и скользящих подсветок; свернутый сайдбар по-прежнему всплывает при наведении на левый край.

Страница файлов: одна сетка для папок проектов и файлов, карточки одинаковой высоты, названия в одну строку, без отдельной плашки для записей Plaud.

## Проверки

- `npm run check`: TypeScript, 281 unit тест в 26 файлах, production сборка. Среди них: слияние блоков документа (включая случайные проверки на 400 раундов), живой редактор, файлы на диске и права на загрузки, напоминания и их проверка сервером, фото, архив проектов и заголовки вкладок, живые дельты и аудит контента, реакции и ссылки в комментариях, почта, офлайн-режим, шаблоны и повторяющиеся задачи, CSV/Markdown/PDF экспорт.
- `npm run e2e`: вход и роли; два аккаунта, где упоминание появляется во входящих коллеги без перезагрузки, оба видят друг друга на странице проекта, а набор в брифе проекта сразу появляется в открытом редакторе коллеги; потеря и восстановление сети со спокойной офлайн-плашкой; спринты, входящие с напоминанием о сроке и архив проекта в демо; мобильная раскладка.

## Что остается на следующие итерации

1. Посимвольное совместное редактирование документов (Yjs). Сейчас текст сливается по блокам: правки разных абзацев сохраняются обе, а одновременный набор в одном абзаце решает последнее сохранение этого абзаца. Когда коллега переносит блок под другого родителя, открытый редактор перерисовывает документ целиком (курсор возвращается по id блока, старые шаги отмены могут не примениться). Код живого обновления опирается на внутренности BlockNote 0.55.
2. Исправлено: после чужого сохранения клиент теперь получает по SSE точечную дельту вместо полной перезагрузки пространства, если ее можно посчитать безопасно и она не больше примерно 512 КБ; иначе, как раньше, вкладка перезагружает всё пространство. Фото профиля (5–20 KB каждое) все еще лежат в JSON пространства, их можно перенести в хранилище файлов.
3. SSE, присутствие и папка файлов живут на одном сервере. Для нескольких инстансов нужен общий брокер (например, Redis pub/sub) и объектное хранилище файлов (например, S3).
4. Файлы отдаются без HTTP Range: видео и аудио скачиваются целиком. Коллеги получают запись о новом файле раньше, чем загрузятся байты, и видят иконку вместо превью до повторного открытия.
5. Исправлено частично: письма с приглашением и восстановлением пароля подключены (SMTP переменные, ссылка одноразовая и с истечением), но нет OAuth-входа, уведомлений на почту о событиях внутри продукта (кроме приглашения и сброса пароля) и серверного планировщика. Напоминания о сроках все еще пишет браузер участника, пока Done открыт.
6. Корзина участников без прав администратора не сохраняется на сервере: удаление можно отменить из тоста, а восстановление из корзины доступно администраторам. Общий файл, удаленный не администратором, теряет байты примерно через 48 часов.
7. Исправлено: журнал аудита теперь пишет и изменения контента (создание, удаление, переименование, архив, корзина), с фильтром Все / Доступ / Контент и подгрузкой старых записей; массовые изменения сворачиваются в одну строку «и еще N».
8. Вошло в эту итерацию: экспорт в CSV, Markdown и PDF; офлайн-режим с сохранением очереди правок в IndexedDB и восстановлением при следующем входе; живые дельты и аудит контента; реакции и ссылки на задачи/страницы в комментариях; письма с приглашением и сбросом пароля; шаблоны задач и повторяющиеся задачи. Осталось без изменений: посимвольное совместное редактирование (Yjs), общий брокер событий и объектное хранилище файлов для нескольких инстансов сервера, отдача файлов с HTTP Range, OAuth-вход.
